# Camera-Ready Experiment Outputs

All results for the EMNLP camera-ready revisions, generated per the meta-review
commitments. Model: Qwen 3.5-35B (generation), Gemini 3.1 Flash Lite (judge).
Monitor running jobs with `bash scripts/cr_status.sh`.

## E1: Second human annotator (`e1_human/`)

- `annotator2_labels.csv` — blank blinded sheet, same 120 claims as the first
  annotator but re-shuffled (seed 7) with fresh blind IDs A001–A120.
- `ANNOTATOR2_INSTRUCTIONS.md` — instructions to send with the sheet.
- `annotator2_private_id_mapping.json` — DO NOT send; maps blind IDs back to
  original claim IDs for scoring.
- Scoring (offline, after sheet returns): join with
  `rebuttal_validation/human_taxonomy_120/human_labels.csv` via the two
  mapping files, compute Cohen's kappa on C0–C8 categories and on the
  binary leakage decision, plus per-class confusion.

## E3: Snapshot-RAG scale-up (`e3_snapshot/`)

- `sample_350.jsonl` — 350 seeded treatment questions (seed 42) from
  `data/binary.jsonl`, each with candidate archive URLs.
- `crawl_progress.jsonl` / `snapshot_contexts.json` — Wayback crawl results
  (up to 3 candidate URLs per question, latest pre-cutoff snapshot, usable if
  >= 500 chars extracted text).
- `gen/snapshot_rag/` — Snapshot-RAG completions on the seeded 200-question
  subset; `gen/snapshot_rag/dataset.jsonl` defines the matched question set.
- `gen/live/b3/`, `gen/live/b4/` — fresh Temporal RAG and TimeSPEC completions
  on the same matched questions.
- `eval/{snapshot_rag,b3,b4}/` — full Shapley-DCLR evaluation per arm.
- `comparison.json` — per-arm means with 95% bootstrap CIs and paired
  bootstrap deltas (DCLR / OLR / performance).
- `full_usage_log.jsonl`, `smoke_usage_log.jsonl` — per-call token/cost logs.

## E5: Shapley vs. simpler metrics (`e5_shapley/`)

- `probe_metric_comparison.json` — from the cached 337-instance task-probe
  results (`runtime/task_sensitivity_eval/full/b1..b4`): OLR vs. DCLR
  correlations, Top-K (K=1,3,5) leakage from Shapley rankings, LOO-weighted
  leakage from cached coalitions (coverage 100%, no API top-up was needed),
  and identical-OLR/divergent-DCLR instance pairs.
- `e3_binary_metric_comparison.json` — same analysis replicated on the fresh
  ~200-question binary arms (snapshot_rag/b3/b4), written by the E3 chain.
- Generated by `scripts/cr_e5_metric_comparison.py` (offline; rerunnable).
- `scripts/cr_loo_topup.py` exists for topping up missing LOO coalitions if
  a future cache is incomplete.

## E6: Cost instrumentation (`e6_cost/`)

- `sample_100.jsonl` — 100 seeded treatment questions (seed 123).
- `full/` — instrumented b1–b4 generation outputs; `eval/b1..b4/` — standard
  evaluations.
- `full_usage_log.jsonl` — every LLM/search call tagged with component
  (generator / judge_client / perplexity / coalition_predictor) and stage
  (phase1a_generation, phase1b_generation, query_generation, rag_retrieval,
  supervisor_taxonomy, search_escalation, search_reverify, regeneration,
  aggregation, judge, shapley_coalition) with tokens, provider-reported cost,
  and latency.
- Build the cost table:
  `python scripts/cr_e6_cost_table.py --usage-log camera_ready/e6_cost/full_usage_log.jsonl --output camera_ready/e6_cost/cost_table.json --n-questions 100`
- Cross-check against `usage_snapshots.jsonl` (root of camera_ready/), which
  records the OpenRouter key's cumulative dollar usage before/after each stage.

## Logs (`logs/`)

One `<job>.log` + `<job>.pid` per detached job (e3_crawl, e3_full, e6_full).
All jobs checkpoint to disk and resume when relaunched with the same command.
